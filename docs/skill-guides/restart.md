# session:restart — 중단 직후 같은 세션에서 재개

> **한 줄 요약** — API 에러·OOM·인증 만료·ESC 로 죽은 턴을 같은 세션에서 이어받아, 다음 실패 비용이 작아지도록 더 잘게 쪼갠 실행으로 되돌린다.

> **[Claude Code 전용]** 세션 TodoList 를 읽고 쓰는 `TaskList` / `TaskUpdate` 가 필요하다.
> 대부분의 하네스는 쓰기 전용 todo 도구만 노출하므로 실패 대신 **degrade** 한다 —
> 마지막으로 완료된 tool 결과에서 재개 대상을 고르고 `git status --short` 로 교차 확인한다.
> 청킹과 위임 규칙은 그대로 유지된다.

## 언제 쓰나

- 턴이 죽었지만 세션은 살아 있을 때 ("이어서 해줘", "끊긴 데서 재개", "다시 로그인했어")
- 사용자에게 처음부터 다시 시키고 싶지 않을 때

## 언제 안 쓰나

| 상황 | 대신 쓸 것 |
|---|---|
| 토큰 리밋 리셋 후 크론이 깨워서 재개 | `session:resume-after-limit` |
| 컨텍스트가 차서 다음 세션에 넘겨야 함 | `session:handoff` |
| 세션이 잘 끝났는지 감사만 | `session:close` |

## 호출 형식

```
/session:restart
/session:restart -h
```

인자가 없다. 재개 대상은 현재 세션의 TodoList 에서 읽는다.

## 동작 단계

1. **재개 대상 식별** — `TaskList` 의 유일한 `in_progress` 항목이 재개 대상이고,
   `git status --short` 한 번으로 교차 확인한 뒤에 움직인다. 아무것도 고를 수 없으면
   멈추고 사용자에게 묻는다.
2. **announce + 더 작은 단계 계획** — 무엇을 이어받았는지 한 줄 먼저 찍는다.
   그래야 사용자가 싸게 교정할 수 있다. 필요하면 `TaskUpdate` 로 `in_progress` 표시.
3. **큰 출력은 위임** — 광범위 검색, 전체 저장소 `find`, 다중 파일 정합성 검사는
   서브에이전트로 보내고 응답을 약 200 단어로 제한해 메인 컨텍스트를 얇게 유지한다.
4. **실행 후 반납** — 각 단계마다 TodoList 를 갱신하고 한 줄씩 보고한다. 원래 끊겼던
   작업이 끝나면 사용자의 이전 흐름으로 제어를 돌려주되, 반드시 `Next:` 한 줄로 마친다.

## 주의사항 / 제약

- **이미 출력이 대화에 있는 process 스킬을 다시 돌리지 않는다.** 컨텍스트에서 결과를 읽는다.
- **"효율을 위해" tool 호출을 묶지 않는다.** 직전 배치가 중간에 죽었다는 것이 이 스킬의 전제다.
- **TodoList 항목의 제목을 고치지 않는다** — 상태만 바꾼다. 제목을 다시 쓰면 사용자의 의도가 사라진다.
- **Step 2 announce 줄을 조용히 건너뛰지 않는다.**
- **다른 스킬 안에서 이 스킬을 호출하지 않는다.** 사용자가 직접 트리거하는 복구 수단이지
  빌딩 블록이 아니다.
